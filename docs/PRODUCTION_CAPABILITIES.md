# 生产化能力与部署边界

本项目以真实电商业务落地为设计准则，仓库提供技术原型、Mock 数据、评测脚本和生产边界说明。当前本地可运行能力与企业生产部署能力必须区分：SQLite 可用于订单、商品、物流和优惠券的本地验证，但生产订单数据由领域服务拥有；Docker Compose 是验证入口，不等于完整生产集群。

## 1. 已落地或可复现的原型能力

### 身份与租户

- API 层解析 Bearer JWT，生成租户、用户和角色上下文。
- URL 中的 `user_id` 只做一致性校验，不能覆盖令牌主体。
- 会话、MCP 工具上下文、知识查询和缓存命名空间使用认证声明。
- 工单按租户隔离，支持角色和资源属性校验。

### 多智能体与故障隔离

- Gateway、Manager、Order/Product/Logistics/Coupon/Policy 能力域按边界协作。
- Manager 输出结构化任务计划，后端执行 Schema、白名单、参数、数量和风险校验。
- 独立子任务有超时、异常隔离和有限重试；查询部分失败可返回部分结果，关键写操作失败则停止或转人工。
- Manager 采用无状态多副本设计时，checkpoint 放 Redis，工单和审计放 PostgreSQL；共享存储仍需单独高可用。

### 退款与工具安全

- MCP 只暴露白名单能力，工具 Schema 不暴露用户身份参数。
- 身份由认证上下文运行时注入，MCP 服务端再次校验租户和资源归属。
- 退款必须经过草案、用户确认、幂等执行和审计留痕。
- 幂等键降低重复执行风险，不承诺单靠客服系统杜绝支付渠道重复扣款或资金对账问题。

### 知识库与缓存

- Milvus 作为生产主检索后端，同时承载 Dense、BM25 稀疏向量和元数据。
- 知识按独立 Collection 不可变发布；上线前构建、评测、引用检查和预加载，回滚只切换旧版本指针。
- FAISS 仅用于本地复现或显式降级，不是生产主方案。
- Redis 语义缓存按租户、知识版本和可见范围隔离；政策 FAQ TTL 24 小时，静态商品信息 TTL 30 分钟；订单、物流、价格、库存和退款状态不做普通语义缓存。

### 观测与数据治理

- Prometheus 记录延迟、P95/P99、错误、缓存命中率、任务数和工具失败率。
- Langfuse 追踪 Agent、工具、模型、知识版本、Token 和成本；订单号、手机号、地址等敏感字段脱敏。
- Trace、指标和日志异步上报，观测系统故障不能阻塞用户请求。
- PostgreSQL 保存租户、工单、退款命令、确认令牌和审计事件；生产订单由订单域服务管理。

## 2. 生产部署建议

1. 在网关或身份平台完成 TLS、OIDC 登录、限流和 JWT 签发，应用只验证约定声明。
2. 将 PostgreSQL、Redis、Milvus、对象存储/索引卷和订单等领域服务部署为受管依赖，应用实例水平扩容。
3. 发布顺序为：知识审核 -> 离线建库 -> 固定评测和引用检查 -> 迁移数据库 -> 灰度发布 -> 观察错误、延迟和业务反馈。
4. 生产机密通过密钥管理注入，不写入 `.env` 或镜像；日志和 Trace 设置采样、保留期和访问权限。
5. Redis 和 PostgreSQL 采用主从、哨兵或集群等高可用方案，否则 Manager 多副本无法真正恢复会话和工单状态。

## 3. 降级策略

| 依赖故障 | 处理方式 |
|---|---|
| 单个领域 Agent 超时 | 返回其他成功结果，提示失败领域 |
| Reranker 超时 | 使用 Dense+BM25 融合排序 |
| Milvus 不可用 | 政策问题拒答或转人工，不按模型记忆回答 |
| MCP 查询超时 | 返回处理中或部分结果，写操作不自动重试 |
| Redis checkpoint 不可用 | 生产实例不接收新流量或进入明确降级 |
| Langfuse/Prometheus 不可用 | 异步上报失败可丢弃，不阻塞主链路 |
| LLM 不可用 | 有限重试后转人工，避免无限重试雪崩 |

## 4. 如实表述边界

- 当前仓库的订单、商品、物流和优惠券数据可以是 SQLite Mock；生产路径通过领域服务适配器体现跨服务边界。
- 当前知识版本注册表和部分部署配置可采用本地实现；生产应替换为集中式配置、对象存储和受管发布系统。
- “路由 91.2%、Hit@3 91%、MRR 0.88、缓存命中 FAQ P95 0.5 秒、Token 降低约 60%”均是固定评测或压测口径，不应表述成所有线上流量的无条件指标。
