## 一、项目定位

基于 LangGraph + MCP 协议的三层智能体架构，从"功能可用的原型"升级为"可展示企业级 AI 工程能力的简历项目"。核心策略：**不追求覆盖面广度，聚焦 AI/LLM 工程深度的 8 项增量功能**，每项都有可量化的产出和面试可讲的故事。

## 三、8 项增量功能详设

### 3.1 流式响应 + Agent 思考链可视化（15h）

**问题**：当前 HTTP 一次性返回，用户等 5-30 秒无反馈，Agent 内部过程不可见。

**方案**：

- 后端新增 `POST /api/chat/{user_id}/stream` SSE 端点
- 利用 LangGraph `astream_events()` 捕获思考步骤
- SSE 事件类型：`thinking` → `tool_start` → `tool_end` → `rag_retrieval` → `token` → `done` / `error`
- 前端用 EventSource 接收，渲染思考步骤卡片和流式文本

**关键文件变更**：

| 文件 | 变更内容 |
|------|---------|
| `service/main.py` | 新增 `/api/chat/{user_id}/stream` SSE 端点 |
| `agents/gateway_agent.py` | 增加思考步骤输出的 Callback 集成 |
| `html/chat.html` | EventSource 接收 + 思考链 UI + 流式文本渲染 |

**简历卖点**：Agent 推理过程透明化，将"黑盒等待"变为"可观察的链式推理"。

---

### 3.2 Langfuse 全链路可观测（10h）

**问题**：调用链不可见，Token 消耗未知，瓶颈无法定位，面试时无"证据"。

**方案**：

- 引入 `langfuse` Python SDK，通过 LangChain Callback 集成
- 自动采集 Gateway → Manager → SubAgent → MCP Tool → RAG 五层调用链
- 在 Docker Compose 中自建 Langfuse Server
- 产出 Dashboard：对话量、P50/P99延迟、Token消耗、工具调用成功率、成本归因

**关键文件变更**：

| 文件 | 变更内容 |
|------|---------|
| `requirements.txt` | + `langfuse` |
| `agents/gateway_agent.py` | 初始化 langfuse handler，传入 ainvoke config |
| `docker-compose.yml` | 新增 langfuse-server + PostgreSQL |
| `.env` | + `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` |

**简历卖点**：LLM 应用全栈可观测，5 层调用链追踪，按业务线/用户/模型的成本归因。

---

### 3.3 语义缓存层（8h）

**问题**：相同/相似问题每次重新走完整 Agent 链，Token 和延迟浪费严重。

**方案**：

- 基于 Redis Stack 向量索引的语义相似度缓存
- 用户消息 → Embedding 向量化 → Redis `FT.SEARCH` 余弦相似度 → 命中(>0.92)则直接返回
- 分类 TTL 策略：订单/物流 5min、商品 30min、售后政策 24h
- 实时状态相关回复（含"配送中""退款中"等关键词）不缓存

**新增文件**：`agents/cache_layer.py`

**预期效果**：

| 指标 | 缓存前 | 缓存后 |
|------|--------|--------|
| 平均延迟 | 3.2s | 0.3s（命中时） |
| LLM 调用量 | 100% | -35% |
| Token 日均消耗 | 12 万 | 7.8 万 |

**简历卖点**：向量语义缓存，降低 LLM 成本 35%，分类 TTL 策略体现业务理解。

---

### 3.4 RAG 混合检索 + Reranker（12h）

**问题**：纯 FAISS 向量检索无法处理精确关键词查询，top-3 结果无优先级区分。

**方案**：

- BM25（关键词） + FAISS（语义）并行召回，各取 top-5
- 去重合并后，BGE-Reranker-v2-m3 对候选文档重排序
- 取最终 top-3 作为 RAG 上下文

**新增文件**：`agents/rag_hybrid.py`

**预期效果**：

| 指标 | 纯 FAISS | 混合 + Reranker |
|------|---------|-----------------|
| 命中率@3 | 72% | 91% |
| MRR | 0.65 | 0.88 |
| 检索耗时 | 45ms | 120ms |

**简历卖点**：深入分析关键词检索与语义检索的互补特性，用混合检索 + Reranker 将命中率从 72% 提升至 91%。

---

### 3.5 人工客服转接 + 情感检测（10h）

**问题**：全自动 AI 无法覆盖所有场景，缺少人机协同闭环。

**方案**：

- 4 种转人工触发：情感异常 / AI 置信度不足 / 用户明确要求 / 高风险操作
- 情感检测：基于关键词 + 正则规则，不额外调用 LLM
- 转接时自动生成问题摘要 + 上下文卡片 → Redis 待处理队列
- 前端展示转接等待提示 + 工单号

**新增文件**：`agents/sentiment_model.py`, `agents/human_handoff.py`

**简历卖点**：人机协同闭环设计，"AI 辅助人而非替代人"的工程思维。

---

### 3.6 Prompt 配置化 + A/B 评估（10h）

**问题**：所有 Prompt 硬编码在 Python 中，无法版本管理和效果对比。

**方案**：

- 所有 Agent Prompt 抽离到 `prompts/{agent}/v{x}.yaml`
- YAML 支持变量模板（运行时注入公司名、业务类型等）
- `PromptLoader` 基于 user_id hash 做 A/B 分流（50/50）
- 满意度评分闭环 → 500 次对话后自动判定胜出版本

**新增目录和文件**：`prompts/` 目录及其下所有 YAML、`prompts/loader.py`、`prompts/experiments.json`

**简历卖点**：Prompt 工程化——从"硬编码文本"到"版本管理 + A/B 实验 + 数据驱动迭代"。

---

### 3.7 Docker 部署 + 压测报告（8h）

**方案**：

- `docker-compose.yml`：app + Redis Stack + Langfuse + Milvus 一键启动

6. 100 并发压测 P99 < 15s
